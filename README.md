# 汐入町（しおいりちょう） — AIが人格を持って育てる、海辺の小さな町

このリポジトリは、**Claude Code の routine（定期実行）機能**を使って、
ひとつのAIが人格を持った「町の記録者」になりきり、
**定期的に目を覚まして町の様子を読み込み → その日の出来事を綴り → 町の状態を更新 → コミット／プッシュ**
を静かに繰り返していくための仕組みです。

舞台は海辺の小さな町・**汐入町（しおいりちょう）**。
コードによる数値シミュレーションは置かず、AIが状態ファイル（JSON / Markdown）を
読み解いて物語を進めていく **AI駆動** の設計です。住人たちのささやかな日常と、
そっと芽生えるさまざまな想いを、急がず、ていねいに育てていきます。

> 語り手AI **灯（あかり）** が、古い灯台から町を見守っています。

---

## 仕組みの全体像

```
            ┌──────────────────────────────────────────────┐
   routine  │  毎日 1 回、灯（あかり）が目を覚ます            │
  （定期実行）│                                              │
            │  1. town/ の現在の状態を読み込む               │
            │  2. routine/RULES.md に沿って「今日」を進める   │
            │  3. 出来事を chronicle/ に日記として綴る        │
            │  4. town/ の状態ファイルを更新する             │
            │  5. コミットして固定ブランチへ push する        │
            └──────────────────────────────────────────────┘
                              ↓ 次の日へ
```

各 routine 実行が、町の **1日** に相当します（実行間隔は routine の設定次第。現在の設定は 2 時間ごとです）。

### 暦と台帳の約束

- **暦は決定論的**です。第1日 = 2026-04-06（月）で、日付・曜日・季節・行事は `routine/calendar.py` が通算日数から導きます。
  AI は `day` を進めるコマンドを打つだけで、日付を手で書きません。
- **台帳は「いまの状態」だけ**を持ちます。過去は `chronicle/` と git log にあります。
  伏線は `town/threads.md` に 1 行ずつ置き、回収したら消します。
- `routine/lint.py` が各ファイルの上限と暦の整合を検査し、超えていればコミットさせません。

## ディレクトリ構成

| パス | 役割 |
| --- | --- |
| `persona/akari.md` | 語り手AI「灯（あかり）」の人格設定。実行のたびに最初に読む |
| `routine/PROMPT.md` | routine に登録する**実行プロンプト本体**。1回分の手順 |
| `routine/RULES.md` | 町を育てるうえでの進行ルール・ペース配分・トーン |
| `routine/calendar.py` | 通算日数から日付・曜日・季節・行事を決める暦スクリプト（`next --write` で翌日へ） |
| `routine/lint.py` | 台帳の肥大化ガード。上限超過や暦の不整合があればコミットさせない |
| `town/meta.json` | 町の現在の日付・曜日・季節・天気・通算日数（暦の項目は `calendar.py` が書く） |
| `town/stats.json` | 人口・幸福度・賑わいなどの指標 |
| `town/map.md` | 町の地図、地区、建物の一覧 |
| `town/residents/*.md` | 住人ひとりひとりのプロフィールと近況 |
| `town/relationships.md` | 住人どうしの関係の段階と、段が動いた日の履歴 |
| `town/threads.md` | 伏線・持ち越しの糸。1 糸 1 行、回収したら消す |
| `chronicle/NNNN.md` | 1日ごとの年代記（灯の日記） |
| `archive/` | 圧縮前の古い台帳。routine は読まない |

## routine のセットアップ手順

> routine は Claude Code on the web / Desktop の機能です（リサーチプレビュー）。
> 詳細: <https://code.claude.com/docs/en/routines>

### 1. このリポジトリを GitHub に用意する

`town`（または `main`）ブランチに、この一式が入っている状態にします。
状態を積み上げていくため、routine が**同じブランチに push し続けられる**必要があります。

### 2. routine を作成する

CLI なら、任意のセッションで：

```text
/schedule daily at 8am, 汐入町の今日を進める
```

あるいは Web（<https://claude.ai/code/routines>）の **New routine** から作成します。

設定内容：

- **Prompt（指示）**: 下の「実行プロンプト」をそのまま貼り付ける
- **Repository**: このリポジトリを選ぶ
- **Trigger**: Schedule → `daily`（毎日1回。お好みで weekly でも可）
- **Permissions**: 育て続けるブランチ（例 `town`）へ push できるよう
  **Allow unrestricted branch pushes** を有効にする
  - ※有効にしない場合、routine は `claude/` 接頭辞ブランチにしか push できず、
    状態が翌日へ引き継がれません。

### 3. 実行プロンプト

routine の Prompt 欄には、次の一行だけを入れれば十分です（手順本体はリポジトリ内にあります）：

```text
あなたはこのリポジトリの routine 実行です。まず persona/akari.md を読んで「灯（あかり）」になりきり、
次に routine/PROMPT.md の手順に厳密に従って、汐入町の「今日」を1日だけ進めてください。
作業対象ブランチは `town` です。最後に必ずコミットして push してください。
```

### 4. 動かしてみる

routine 詳細ページの **Run now**、または CLI の `/schedule run` で初回を実行できます。
`chronicle/` に新しい日記が増え、`town/` の状態が更新され、push されていれば成功です。

## 自分で読むときは

物語の続きを追うには `chronicle/` を古い番号から順に読んでください。
町の「いま」を知りたいときは `town/meta.json` と `town/residents/` を覗いてみてください。

灯は、誰かをせかしたりしません。
小さな町の、小さな幸せが、ゆっくり積もっていくのを見守ってあげてください。
